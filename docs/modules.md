# Модули «Своей ГИС»

**Всё, кроме поиска, места, экрана способов, маршрута и ведения, — модули.** Даже способы передвижения: метро, пешком, такси и каршеринг — отдельные модули. Ядро не знает ни одного способа: оно спрашивает модули «чем можно добраться?».

Ядро приложения о модулях ничего не знает. Оно спрашивает **включённые** модули в четырёх точках встраивания и показывает ответы в своём стиле. Модуль отдаёт данные, а не разметку — поэтому не может сломать вид или тон приложения.

## Шлюз
Все ответы модулей проходят через шлюз:
- **ошибка** в любом хуке — модуль отключается до конца сеанса (на экране «Модули» помечен «выключен из-за ошибки»), остальное работает;
- **проверка формы** — неподходящие ответы отбрасываются (не массив, нет текста, точка без координат);
- **экранирование** — текст модуля выводится как текст, код из него не выполняется;
- **копии** — ядро работает с проверенной замороженной копией варианта; модуль может менять свой объект, но до экрана это дойдёт только через новую проверку. Шаг, который получает модуль (`leg`), — тоже замороженная глубокая копия: модуль не может испортить маршрут;
- **ограничения** — множитель времени шага 0,5–3; не больше 2 подсказок на экране способов, 2 у шага, 2 пилюль, 6 точек;
- **ключ прогноза** учитывает время поездки, включённые модули и их факты: сменилось время, включил, выключил, изменились данные — способы готовятся заново (`prepare`), прогноз пересчитывается;
- **повторная регистрация** того же id заменяет модуль, а не добавляет второй.

## Как добавить модуль
Описать объект и вызвать `registerModule()` — больше ничего менять не нужно. Экран «Модули» соберётся сам.

```js
registerModule({
  id: 'lifts', icon: '🛗', name: 'Лифты и эскалаторы',
  desc: 'Ремонт эскалаторов и закрытые входы', where: 'в шагах метро', on: true,
  context(T)            { return { repair: ['Бауманская'] }; },          // свои данные на время поездки
  legFactor(leg, f)     { return leg.station && f.repair.includes(leg.station) ? 1.3 : 1; },   // 1. прогноз (вход и подъём)
  stepHints(leg, t, f)  { return leg.station && f.repair.includes(leg.station)
                            ? [{ icon:'⚠️', text:'Эскалатор на ремонте — подъём дольше', warn:true }] : []; }, // 2. шаги
  banners(f)            { return []; },                                   // 3. экран способов
  cardPills(k, f)       { return []; },                                   //    пилюли в карточке способа
  pois(k, f)            { return []; }                                    // 4. точки на карте и «По пути»
});
```

## Как убрать модуль
Удалить его объект (или `unregisterModule(id)` на ходу). Ядро и другие модули не трогаются, следов в настройках не остаётся. Выключенный пользователем модуль не опрашивается совсем — ни на прогноз, ни на экраны.

## Модулю доступно
- `leg` — **копия** шага (менять бесполезно): `type`, `label`, `model` (`board` — вход и платформа, `ride` — поездка, `exit` — подъём), `station`, `stations`, `k` — способ (`metro`, `taxi`, `carshare`, `walk`, `stroll`, `loop`).
- `refreshModules()` — попросить пересчёт, когда у модуля появились свежие данные (например, погода).
- Подсказки шагов (`stepHints`) видны и на маршруте, и во время поездки — в верхней плашке ведения.

## Модуль-способ передвижения
`group: 'mode'`. Отдаёт варианты маршрута (`options`) и, если время зависит от часа, готовит их на время поездки (`prepare(T, f)`). Свои данные (линия метро, точки, станции) модуль держит у себя — ядро о них не знает.

Пример — велосипед, **без единой правки ядра** (тот же код — в автопроверке `tests/run.js`):

```js
registerModule({
  id:'bike', group:'mode', icon:'Шаги', name:'Велосипед', desc:'Велопрокат', where:'способы', on:true,
  options: { bike: { name:'Велосипед', ico:'Шаги', price:'≈ 150 ₽', purpose:'go', order:5, detail:'станция в 200 м',
    legs:[
      { type:'walk', label:'До станции проката', lo:3, hi:4, coords:[[37.8111,55.79271],[37.8090,55.7925]] },
      { type:'wait', label:'Взять велосипед', lo:1, hi:3, at:[37.8090,55.7925], parts:[{ tri:[1,2] }, { chance:0.1, add:3 }] },
      { type:'car', label:'На велосипеде до Бауманской', lo:28, hi:38,
        coords:[[37.8090,55.7925],[37.75,55.788],[37.67876,55.77235]], lm:'По выделенной полосе' } ] } }
});
```

**Поля варианта:** `name`, `ico` (имя иконки из набора), `price`, `detail`, `purpose` — `'go'` (добраться) или `'walk'` («Погулять рядом»), `order`, `legs`; по желанию — `verb` («Выходи» / «Вызывай»), `cta` (кнопка старта: «Пошли», «Вызвать такси»), `ctaLate` (когда уже не успеть), `stopLabel` (кнопка остановки: «Закончить путь»), `endToast`, `confirm` (подтверждение перед оплатой: `crumb, title, rows, note, btn`), `startToast`, `riskWord`, `varyWord`, `delayWhy`, `legIco`, `tail` (редкий сбой `[вероятность, от, до]`), `pois`, `requires`, `closed` / `closedInfo`.

**Шаг (`legs[]`):**
- `type` — как ядро рисует и ведёт: `walk` (пунктир), `metro` (поездка по остановкам), `car` (сплошная линия), `wait` (точка, ожидание);
- `label`, `lm` (подсказка), `warn`, `tip`, `kind` (подпись в ведении);
- время: `lo`–`hi` (минут, показывается «обычно lo–hi»); сложное время — `parts`: `{tri:[от,до]}` — диапазон, `{upto:x}` — ожидание от 0 до x, `{chance:p, add:x}` — иногда +x; ядро складывает части;
- где на карте (по приоритету): `coords` — свои координаты; `geom` — готовый маршрут; `stops:[{n, at}]` — остановки (по ним «выходить через N»); `at` — точка; `from`/`to` — построит маршрутизатор;
- `model`, `station`, `stations` — метки для других модулей (вагон, темп): ядро их не читает.

Шлюз проверяет вариант целиком: ключ, непустое `name`, текстовые поля (`detail`, `price`, `verb`, `cta`… — только строки), `tail` (три неотрицательных числа), шаги (`label` обязательна, `lo ≥ 0`, у маршрута в сумме больше нуля минут), части времени, координаты, цвета, отсутствие разметки. Проверка повторяется после каждого `prepare`. Плохой вариант не попадает в приложение, модуль отключается.

## Модуль-поставщик данных
`group: 'data'`. Сам ничего не показывает, отдаёт данные другим модулям. Пример — «Пробки»: `this.use('roads').at(T)` → время за рулём, надпись, сбой. Такси и каршеринг объявляют `requires:['roads']`: выключишь «Пробки» — без них они не работают. В приложении сюда же — погода, ремонты эскалаторов (набор 624), загруженность.

`this.use(id)` — включённый модуль по id (или `null`); пользоваться можно только тем, что объявлено в `requires`.

## Зависимости
`requires: ['metro']` — модуль работает, только если включены эти модули. «Загруженность вагонов» требует метро, «Кофе по пути» — «Пешком». На экране «Модули» у такого модуля написано «Не работает без: Метро».

## Точки встраивания
| Точка | Хук | Что возвращает |
|---|---|---|
| Свои данные | `context(T)` | факты на время поездки T (минуты суток) → `CTX.mods[id]`; изменились факты — прогноз пересчитывается |
| 1. Прогноз | `legFactor(leg, f)` | множитель времени шага (1 — без изменений) |
| 2. Шаги маршрута | `stepHints(leg, t, f)` | `[{icon, text, warn}]` — белая плашка или оранжевое предупреждение |
| 3. Экран способов | `banners(f)`, `cardPills(k, f)` | подсказки над карточками, пилюли в карточке |
| 4. Карта | `pois(k, f)` | `[{e, n, d, at, extra}]` — «По пути» и метки на карте |
| 5. После поездки | `afterTrip(info, f)` | `{title, text, choices:[{id, label, only}], multi}` — вопрос на «Ты на месте»; `info` — способ, типы шагов, время |
| | `answer(ids, info, f)` | `{title, lines, foot}` — что модуль учёл; показывается вместо вопроса |
| Главный | `homeCards(next, f)` | `[{icon, title, text, go, warn}]` — одна плашка на главном. `next` — ближайший сохранённый маршрут на сегодня (с учётом дней): `name, place, mode, modeName, verb, L` («выйди до»), `arrive, late, why` (что сейчас влияет на путь). `go` — кнопка «Маршрут» |
| Настройки | `settings(f)` | `{rows:[[название, значение]], note, reset, pick:{title, options:[{id, label}], sel}}` — экран модуля по ссылке «Подробнее» в «Модулях»; выбор из `pick` приходит в `onPick(id)` |

**Хранилище модуля:** `this.store.get()`, `set(v)`, `clear()` — своё у каждого модуля, только на этом телефоне.
Если у модуля есть `schema`, ядро отдаёт из хранилища только проверенные значения: `{ поле: [мин, макс, по умолчанию] | true/false | 'текст' }`. Битое, старое или чужое значение заменяется значением по умолчанию, лишние поля отбрасываются — так испорченная запись не ломает прогноз. Пример — «Мой темп»: `walkK:[0.5, 2, 1]`.
**Зависимости на экране.** Выключаешь модуль, на который опираются другие («Пробки» → такси и каршеринг), — приложение сначала предупреждает, кто перестанет работать. «Включить» (в «Модулях» и в пустом состоянии) включает модуль вместе со всем, без чего он не работает, — в том числе с `requires` его вариантов (прогулка у Яузы требует «Пешком»). Если способ включён, но ждёт выключенный модуль данных, на экране способов — строка «Такси и Каршеринг — не работают без «Пробки»» с кнопкой «Включить». Для модулей и проверок без вопросов: `setMod(id, true/false)`.

**Другие модули — только через `this.use(id)`** и только если `id` объявлен в `requires`; иначе `null` и предупреждение в консоли. Так зависимости модуля всегда видны в его описании.

**Между сеансами** сохраняются шаблоны, недавние места, визиты, отказы от предложения сохранить и включённость модулей (`gis.app`, только на этом телефоне). При чтении всё проверяется: неизвестные места, чужие модули и битые записи отбрасываются.

«Демо: начать с первого запуска» сбрасывает всё: хранилища всех модулей, включённость по умолчанию, отметки «выключен из-за ошибки», кэш прогноза.

`f` — факты этого модуля из `context()` (или `{}`), всегда последний аргумент.

## Модули сейчас
Способы передвижения:
- **Метро** — интервалы по времени суток, глубина станций, ночью закрыто; варианты «Метро» и «Метро + прогулка у Яузы».
- **Пешком** — «Пешком» и «Просто погулять».
- **Такси** — подача, пробки по времени суток, подтверждение перед вызовом.
- **Каршеринг** — ближайшая машина, пробки, подтверждение перед бронью.

Данные:
- **Пробки** — загруженность дорог по времени суток (нужны такси и каршерингу).

Подсказки:
- **Погода в пути** — дождь замедляет пешие шаги на 6%, подсказка «Дождь с 8:40», «нужен зонт» у пешего варианта.
- **Загруженность вагонов** — подсказка в шаге метро, если посадка в 8:30–8:50.
- **Кофе по пути** — кофейни в «По пути» на прогулках (нужен «Пешком»).
- **Мой темп** (калибровка) — после первой поездки «Как ты обычно ходишь?», дальше «Что-то задержало?» (несколько причин, «Всё как обычно» исключает остальные); ответы меняют время пеших шагов, ожидания поезда и подъёма; экран «Подробнее» со сбросом.
- **Вагон для выхода** — «Садись в первые вагоны: на Бауманской выход у головы поезда» по данным `data/metro-cars.json`; нет записи для станции — молчит (нужно метро).

В ядре — только общее: поиск и места, словарь типов шагов, расчёт прогноза, карта и ведение. Ни одного способа, ни одной линии метро, ни таблицы пробок.

## Шаблоны: дни недели и «Пора выходить» (фаза 2, 25.11.2026)
- У шаблона есть дни (`days`: 0 — пн … 6 — вс). При сохранении «Работа» и «Учёба» сразу получают пн–пт, остальные — «в любой день» (без напоминаний по расписанию). Не в свой день шаблон показывает, когда понадобится: «к 9:00 · пн».
- «Пора выходить» — модуль (`leave`, хук `homeCards`). Напоминает за 10–30 мин (шаг 5, настройка модуля), в момент выхода — «Пора выходить», если уже впритык — оранжевым. Причину берёт из подсказок (дождь, пробки). На телефоне это будет уведомление.
- Служебные модули (`group:'data'` и `service:true` — «Пробки», «Мой темп») на экране «Модули» спрятаны под ссылкой «Служебные модули».
- Демо: в «Модулях» можно передвинуть «сейчас» (8:00–8:23) и день недели.
